### 3p [문서 객체 모델 DOM]

먼저 DOM에 대해 알아보겠습니다. DOM은 '문서 객체 모델'의 약자로, HTML 요소의 계층 구조를 반영하여 만든 객체입니다. 

HTML은 웹 페이지의 **뼈대와 구조**를 만드는 언어입니다. 텍스트, 이미지, 버튼 같은 요소들이 어디에 위치해야 하는지 정의하죠. HTML 자체는 한 번 브라우저에 로드되면 스스로 변하지 않는 고정된 '문서'입니다.

HTML은 단순한 텍스트 파일일 뿐이라서, 자바스크립트 같은 프로그래밍 언어가 직접 HTML 태그를 '이해'하거나 '수정'할 수 없습니다. 여기서 **DOM**이 등장합니다.

브라우저는 HTML 문서를 읽어 들인 후, 이를 자바스크립트가 조작할 수 있는 **객체(Object) 형태의 트리 구조**로 바꿉니다. 이것이 바로 DOM입니다.

HTML로 구성된 웹 페이지와 자바스크립트 같은 프로그래밍 언어를 중간에서 연결해주는 아주 중요한 역할을 합니다.

### 4p [DOM의 계층 구조]

DOM은 다음 그림을 보시면 마치 가계도(Family Tree)처럼 부모와 자식 관계가 형성되어 있는 트리(Tree) 자료 구조를 가집니다.

최상위 'document'를 시작으로 HTML, Body, 그리고 하위의 Div와 같은 엘리먼트 노드, 텍스트 노드, 속성 노드들이 마치 나무 뿌리처럼 연결되어 있습니다.

### 5p [DOM에 접근하는 방법]

그렇다면 자바스크립트로 이 DOM에 어떻게 접근할까요? 가장 대표적인 방법은 `document.getElementById(id)`를 사용하는 것입니다. 

`document.getElementById(id)` 메소드를 실행하면 주어진 id를 가지는 DOM 요소를 Element 객체로 가져오고, 문서 안에 해당 id를 가지는 요소가 없으면 존재하지 않는다는 의미인 null을 저장합니다

### 9p [가상돔]

하지만 매번 실제 DOM을 직접 수정하면 브라우저에 과부하가 올 수 있습니다. 그래서 리액트 같은 프레임워크는 'Virtual DOM'을 사용합니다. 

버츄얼 돔이 없었다면, 매번 새로 처음부터 브라우저를 그려야하는데, 버츄얼 돔의 디핑기법으로 브라우저 과부하 문제를 해결 할 수 있습니다.

가상 DOM은 **Diffing**이라는 과정을 거쳐 이전 상태와 현재 상태의 차이점을 찾아냅니다. 그림의 빨간 부분처럼 수정사항이 발생하면, 가상 DOM에서 미리 계산을 마친 뒤 최종 결과물만 실제 DOM에 한꺼번에 전달함으로써 불필요한 렌더링을 방지합니다.

### 10p [컴포넌트 생명주기]

다음은 컴포넌트의 생명주기입니다. 컴포넌트 단어에 대해서 디자인파트나 프론트엔드 파트들을 다들 한 번 쯤 들어보셨을 텐데요.

컴포넌트는 화면을 구성하는 독립적이고 재사용 가능한 조각입니다. 레고 블록처럼 버튼, 헤더, 검색창 등을 따로 만들어두고, 이를 조립하여 웹사이트나 앱 화면을 완성하는 방식입니다. 

컴포넌트는 크게 세 단계의 삶을 삽니다. 처음 화면에 나타나는 '마운트', 상태가 바뀌어 다시 그려지는 '업데이트', 그리고 화면에서 사라지는 '언마운트'입니다. 

마운트 단계에는 컴포넌트 처음 화면에 나타나는 순간으로 이때, API를 호출하거나 이벤트 리스터를 등록합니다.

업데이트 단계는 상태나 props가 바뀔 때마다 컴포넌트가 다시 그려지는 단계입니다.

언마운트 단계는 컴포넌트가 화면에서 사라지는 순간 마운트 때 등록한 이벤트 리스너나 타이머를 제거합니다. 특히 언마운트 때 사용하던 리소스를 잘 정리해줘야 메모리 누수를 방지할 수 있습니다.

---

### 11p [컴포넌트 생명주기 - 예시]

앞서 설명한 세 단계를 `useEffect`로 살펴보겠습니다.

카페 진동벨을 떠올려보세요. 주문자가 바뀔 때만 번호가 새로 울리죠? `useEffect`도 똑같이, 의존성 배열 안의 값이 바뀔 때만 동작합니다.

**마운트** — 카페에 첫 손님이 들어온 순간입니다. 컴포넌트가 화면에 처음 나타나면서 `subscribe(userId)`로 해당 유저 구독을 시작합니다.

**업데이트** — 손님이 바뀌면 진동벨 번호도 바뀌어야겠죠? 1번 유저에서 2번 유저로 바뀌면, 먼저 1번 구독을 끊고(`unsubscribe`), 그다음 2번을 새로 구독합니다(`subscribe`). 항상 **정리 먼저, 시작은 나중**입니다.

**언마운트** — 카페 문을 닫는 시간입니다. 컴포넌트가 화면에서 사라질 때, 마지막으로 연결된 구독을 깔끔하게 끊고 마무리합니다.

### 12p 의존성배열이 비어있는 경우

만약 다음과 같이 의존성 배열이 비어있는 경우, 컴포넌트가 처음 나타날 때 마운트가 딱 한 번만 실행되고, userId가 바뀌어도 새로운 채팅방을 구독하지 않게 됩니다.

카페 진동벨로 비유하게 되면 첫 손님 번호로 하루 종일 벨을 울리게 되고, 다른 손님은 주문이 준비되어도 진동벨 알림을 받을 수 없게 됩니다.

### 14p [상태와 클로저]

다음은 리액트에서 상태를 관리할 때 매우 중요한 개념인 '클로저'와의 관계를 살펴보겠습니다. 리액트 함수 컴포넌트는 상태가 바뀔 때마다 전체가 다시 실행되는 특징을 지니고 있습니다. 따라서 리액트의 `useState`를 사용해 이전의 상태값을 기억할 수 있습니다. 이때 자바스크립트의 클로저 원리가 이용됩니다.

useState를 호출하면, 리액트 내부 메모리에 공간 확보를 할 수 있고, setState 함수를 통해 클로저 매커니즘을 통해 외부 메모리에 대한 영구적 참조가 가능합니다.

함수가 선언될 당시의 환경을 기억하는 클로저 덕분에, 컴포넌트 함수가 호출이 끝난 후에도 내부 변수인 '상태값'에 계속 접근하고 이를 업데이트할 수 있는 것입니다.

### 15p [브라우저 이벤트 흐름 - 캡처링과 버블링]

이제 브라우저에서 이벤트가 어떻게 전달되는지 그 흐름을 알아보겠습니다. 이벤트는 크게 세 단계로 진행됩니다. 첫 번째는 최상위 요소에서 타겟 요소까지 내려가는 '캡처링(Capturing)' 단계입니다.

두 번째는 실제 이벤트가 발생한 지점인 '타겟(Target)' 단계이고, 마지막 세 번째는 다시 타겟에서 부모 요소로 거슬러 올라가는 '버블링(Bubbling)' 단계입니다. 

대부분의 이벤트 핸들링은 이 '버블링' 단계에서 일어납니다.

### 19 [이벤트 위임 예시]

자바스크립트 코드를 통해 이벤트 위임 동작 방식에 대해서 자세히 살펴보도록하겠습니다.

**부모 요소 감시 (Event Listener)** 

첫 번째 단계는 부모 요소를 선택하는 것입니다. 개별 항목인 `<li>`가 아니라 이들을 모두 감싸고 있는 부모 컨테이너인 `<ul>`(`itemList`)에 단 하나의 이벤트 리스너를 등록했습니다. 이렇게 하면 메모리 사용을 획기적으로 줄일 수 있습니다.

**클릭 타겟 파악 (Event Target)** 

두 번째는 실제로 어디가 클릭되었는지 알아내는 단계입니다. 사용자가 리스트 중 하나를 클릭하면 이벤트 객체의 `event.target` 속성을 통해 브라우저는 정확히 어떤 요소를 건드렸는지 우리에게 알려줍니다.

**유효성 검사 (Filtering)** 

세 번째는 유효성 검사입니다. 리스트 내부의 빈 공간이나 텍스트를 클릭했을 때 오작동하지 않도록 `.closest('li')` 메서드를 사용했습니다. 이 코드는 클릭된 지점에서 가장 가까운 `<li>` 요소를 찾아줌으로써, 우리가 원하는 리스트 항목 안에서 클릭이 일어났는지를 확실히 판별해 줍니다."

**동작 실행 (Action)** 

마지막으로 조건에 부합하는 경우에만 원하는 로직을 수행합니다. 여기서는 기존에 선택된 항목의 하이라이트를 지우고, 방금 클릭된 요소에만 `active` 클래스를 추가해 시각적인 효과를 줍니다.

### 21p [이벤트 전파 방지]

이벤트의 흐름을 인위적으로 막는 방법 중 `stopPropagation` 에 대해서 다뤄보겠습니다.

이벤트 위임을 통해 이벤트를 효율적으로 관리할 수 있게 되었지만, 때로는 이벤트가 부모로 퍼지는 것을 막거나 브라우저의 기본 동작을 가로채야 할 때가 있습니다. 이를 '이벤트 전파 방지'라고 합니다.

`event.stopPropagation()` 을 통해 이벤트 버블링을 차단할 수 있습니다.

앞서 보신 것처럼 이벤트는 타겟에서 부모로 거슬러 올라가는 '버블링' 특성이 있습니다. 하지만 특정 버튼을 눌렀을 때, 그 버튼을 감싸고 있는 부모 요소의 클릭 이벤트까지 실행되면 곤란한 경우가 있죠.

이때 `event.stopPropagation()`을 호출하면, 이벤트가 현재 요소에서 멈추고 더 이상 상위 요소로 전달되지 않습니다. 즉, '내 일은 내가 끝냈으니 위로는 알리지 마!'라고 브라우저에게 말하는 것과 같습니다.

### 22p [이벤트 전파 방지 - 예시]

다음은 이벤트 전파 흐름제어를 예시로 보겠습니다.

왼쪽의 화면은 제가 실제로 이전 기수 프로젝트하면서 사용한 모달 화면인데요,

모달은 모달 외부와, 닫기 버튼을 통해서 닫을 수 있습니다. 

모달 영역에 stopPropagation을 적용하지 않을 경우 모달 닫기 버튼을 클릭시, 모달에 대한 요소를 삭제하게 되는데, 버블링을 통해서 모달 바깐 영역에 적용된 닫기함수가 다시 호출되면서 이미 삭제된 모달 요소를 다시 삭제하게 되면서 에러가 발생합니다.

모달 영역에 클릭 이벤트에 대한 stopPropagation을 적용하게 되면, 모달 영역 밖에서 발생하는 이벤트 버블링을 막아주는 동시에 모달 내부에서 모달 닫기 버튼 영역을 제외한 부분을 클릭하면 모달이 닫히는 문제를 해결 할 수 있습니다.
