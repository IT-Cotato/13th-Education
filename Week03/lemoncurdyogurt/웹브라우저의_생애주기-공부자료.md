# DOM

텍스트 파일로 만들어져 있는 웹 문서를 브라우저에 렌더링

→ 브라우저가 이해할 수 있는 구조로 메모리에 올려야함

- DOM
    - 모든 요소 / 요소의 어트리뷰트 / 텍스트를 각각의 객체로 만들고
    - 이들 객체를 부자 관계를 표현할 수 있는 트리 구조로 구성한 것

브라우저는 웹 문서(HTML, XML, SVG)를 로드한 후, 파싱하여 DOM(문서 객체 모델: Document Object Model)을 생성한다.

웹 문서의 동적 변경을 위해 DOM은 프로그래밍 언어가 자신에 접근하고 수정할 수 있는 방법 제공

→ property, method를 갖는 `자바스크립트 객체`로 웹 문서의 동적 변경을 할 수 있음

→ DOM API라고 함

- 정적인 웹페이지에 접근하여 동적으로 웹페이지를 변경하기 위한 유일한 방법
    - 메모리 상에 존재하는 DOM을 변경하는 것
- 이때 필요한 것이 **DOM에 접근하고 변경하는 프로퍼티와 메소드의 집합인 DOM API**이다.

## **DOM tree**

브라우저가 HTML 문서를 로드한 후 파싱하여 생성하는 모델

객체의 트리로 구조화되어 있기 때문


DOM에서 모든 요소, 어트리뷰트, 텍스트는 하나의 객체이며 Document 객체의 자식

요소의 중첩관계는 객체의 트리로 구조화하여 부자관계를 표현

DOM tree의 진입점(Entry point)는 document 객체이며 최종점은 요소의 텍스트를 나타내는 객체


DOM tree의 객체 구성

DOM 트리를 크롬 브라우저에서 확인하려면 개발자도구(Developer Tools)의 Elements 를 선택한 후 오른쪽의 properties을 선택해서 볼 수 있음


DOM을 통해 웹페이지를 조작(manipulate)하기 위해서

- 조작하고자하는 요소를 선택 또는 탐색한다.
- 선택된 요소의 콘텐츠 또는 어트리뷰트를 조작한다.

## DOM 조작

- **`document.getElementById('id')`**
    - 고유한 ID로 요소를 가져옴
- **`document.querySelector('selector')`**
    - CSS 선택자(`.class`, `#id`, `tag` 등)를 사용하여 첫 번째 요소를 반환
- **`document.querySelectorAll('selector')`**
    - 선택자에 맞는 모든 요소를 노드리스트로 반환
- **`document.getElementsByClassName('class')`**
    - 클래스명으로 요소들을 가져옴
- **`document.getElementsByTagName('tag')`**
    - 태그명으로 요소들을 가져옴

# Virtual DOM

가상돔은 실제 DOM의 가벼운 JS객체 복사본

React가 UI 변경 시 메모리에서 효율적으로 이전/이후 트리를 비교(Diffing)하고, 바뀐 부분만 실제 DOM에 반영(Reconciliation)하여 성능을 최적화하는 핵심 기술

## Difffing

이전 가상돔 트리와 새로운 가상돔 트리를 비교하여 차이점을 탐색하는 휴리스틱 알고리즘(O(n))

- 엘리먼트 타입이 다르면 이전 트리를 버리고 새로 구축.
- 타입이 같으면 속성(Attribute)만 변경

## Reconcilation(재조정)

Diffing에서 찾아낸 변경 사항만 실제 DOM에 적용(Batch Update)

# 컴포넌트 생명주기

## 마운트

컴포넌트 처음 화면에 나타나는 순간으로 이때, API를 호출하거나 이벤트 리스터를 등록

## 업데이트

상태나 props가 바뀔 때마다 컴포넌트가 다시 그려지는 단계

## 언마운트

컴포넌트가 화면에서 사라지는 순간 마운트 때 등록한 이벤트 리스너나 타이머를 제거합니다. 특히 언마운트 때 사용하던 리소스를 잘 정리해줘야 메모리 누수를 방지

### useEffect 예시

useEffect: 컴포넌트가 렌더링 될 때마다 특정 작업을 실행하는 함수

의존성 배열에 해당하는 변수의 값이 바뀔 때만 실행됨

카페 진동벨로 비유 하자면, 주문자가 바뀔 때만 진동벨 번호 갱신과 같은 개념

### 의존성 배열 비어있는 경우

- 컴포넌트가 처음 나타날 때(Mount) 딱 한 번만 실행
- userId가 바뀌어도 새로운 채팅방을 구독하지 않음

[카페 진동벨로 비유] 첫 손님 번호로 하루 종일 벨을 울림, 다른 손님은 주문이 준비되어도 진동벨 알림을 받을 수 없음

### 의존성 배열 없는 경우

- 컴포넌트가 리렌더링될 때마다 실행
- 화면이 아주 조금이라도 바뀔 때마다 기존 구독을 끊고 새로 연결합니다 (글자를 입력하거나 다른 버튼을 누를 때마다)

[카페 진동벨로 비유] 숨 쉴 때마다 진동벨 번호 다시 부여, 주방 서버 터짐 (성능 저하)

# 상태와 클로저

리액트 함수 컴포넌트는 상태가 바뀔 때마다 전체가 다시 실행되는 특징을 지님. useState사용하면 클로저 메커니즘을 통해 외부 메모리 공간에 대한 영구적 참조할 수 있음.

### 클로저

렌더링될 때마다 새로 실행되는 컴포넌트 함수가 이전 상태를 기억하는 방법

# 이벤트 전파

캡처링 → 타깃 → 버블링

타깃에서 실행된 후 이벤트가 부모 요소로 전파됨. 브라우저에서의 이벤트는 특정 요소에만 국한되지 않고, 트리를 따라 이동하는 특징이 있음

## 캡처링

이벤트가 최상위 요소(document)에서 시작하여 실제 타깃 요소까지 하위로 내려감

## 타깃

 이벤트가 실제 발생한 요소에서 핸들러가 실행되는 시점

## 버블링

이벤트가 다시 타깃 요소에서 상위 요소로 역방향으로 올라가며 전파되는 단계

### 이벤트 위임

많은 DOM 요소에 각각 이벤트를 등록하는 대신, 부모 요소 하나에만 이벤트를 위임하면 성능과 유지보수 측면에서 훨씬 유리

→ 버블링을 사용하는 기법

자식요소에 특정 이벤트를 각각 등록하는 것이 아니라 부모요소에만 이벤트 등록

- 자식 요소가 타깃이라면 이벤트 발생 시, 버블링을 통해 부모요소까지 올라감
- 부모요소에만 이벤트 리스너 등록하면 클릭 타겟을 통해서 클릭된 실제 자식 요소 판단해서 이벤트 실행시키기

### 이벤트 전파 흐름 제어

'이벤트 캡쳐링'과 '이벤트 버블링'이 이벤트 처리의 유연성과 확장성을 제공하는 목적이지만, 전파되면 안 되는 부분에서 이벤트가 전파되는 것은 기능상의 문제가 될 수 있음

1. **event.stopPropagation()**
    
    이벤트가 상위 DOM으로 전파되지 않도록 하는 기능
    
2. **event.stopImmediatePropagation()**
    
    이벤트가 상위 DOM으로 전파되지 않도록 하는 기능
    
    'event.stopPropagation()' 함수와의 차이점
    
    'event.stopImmediatePropagation()' 함수의 경우 이벤트 대상 DOM에 여러 이벤트가 걸려 있을 때 해당 이벤트들 사이의 전파도 막아 준다는 것입니다.
    
3. **event.preventDefault()**
    
    현재 이벤트의 기본 동작을 중단하는 기능
    
    해당 함수 적용 시 'checkbox'를 클릭했을 때, 기본 동작인 체크는 되지 않고 이벤트 전파만 발생하는 결과를 확인할 수 있음
    
    → 해당 기능은 클라이언트 측의 validation 검사 등에서 활용될 수 있음
    
    - 조건이 만족하지 않을 때 체크박스가 클릭되지 않도록 하기
    - 키 입력에 대해 조건을 주어 특정 키가 입력되지 않게 하는 등
